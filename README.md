# Mismatched granules

Experiments on reading NASA granules as one virtual Zarr array when their layouts do
not match: the compression, chunk shape, chunk boundaries, fill value or data type
changes partway through a record.

The library changes are prototypes on three branches:

| Project | Branch | What it adds |
|---|---|---|
| zarr-python | [`maxj-labs/zarr-python@feat/array-concat-codec`](https://github.com/maxj-labs/zarr-python/tree/feat/array-concat-codec) | `switch` codec, chunk coordinates passed to codecs, `array_concat` codec |
| VirtualiZarr | [`maxj-labs/VirtualiZarr@feat/concat-mismatched-arrays`](https://github.com/maxj-labs/VirtualiZarr/tree/feat/concat-mismatched-arrays) | `set_options(mismatched_concat="pieces")`, `plan_joined_array`, Icechunk writer |
| Icechunk | [`maxj-labs/icechunk@feat/virtual-ref-prefix`](https://github.com/maxj-labs/icechunk/tree/feat/virtual-ref-prefix) | virtual references made of a literal and several byte ranges |

This repository holds what was run against them and what came out.

## Pages

The site is at https://maxj-labs.github.io/mismatched-granules/ and is built into `docs/`
by `python brief/build_pages.py`, which also puts the same navigation on every page.

| Page | Source | What it is |
|---|---|---|
| [Overview](https://maxj-labs.github.io/mismatched-granules/) | `eval/site.py` | the short version: the designs, what happens to each when a store is edited, how often NASA records change away from the end, and what to choose |
| [Storybook](https://maxj-labs.github.io/mismatched-granules/storybook.html) | `eval/storybook.py` | pick an option, or the way your files disagree, and read what follows |
| [Every option, tested](https://maxj-labs.github.io/mismatched-granules/evaluation.html) | `eval/report.py`, `eval/page.py` | sixteen options against the same test cases, edits, worst cases and Daymet |
| [Original proposal](https://maxj-labs.github.io/mismatched-granules/brief.html) | `brief/index.html` | the first write-up: the `switch` codec and virtual shards. Where it disagrees with the newer pages, they are right |

The pages call an entry in the `switch` codec's table a "layout"; the code and the
original proposal call it a "case".

## Layout

| Path | What |
|---|---|
| `brief/index.html` | The write-up: the proposal and the evidence |
| `bench/` | Every approach on the same Daymet files: `compare.py`, `hdr_arms.py`, `refkv_arm.py`, `na_hybrid.py`, `na_shards.py`; `range_server.py` counts the requests that reach the source and can relay to the archive |
| `survey/` | Other collections: `layouts.py` (layouts from metadata-only reads), `pick.py` (find layout change points, download a few granules), `run.py` and `all_vars.py` (join and check), `remote.py` (whole records, metadata only), `test_fill.py` |
| `scripts/` | Daymet download and a first end-to-end build |
| `results/`, `results_http/` | One JSON file per run. `results_http/` holds the runs that counted source requests |
| `bench/vendor/` | The `switch` codec demo from d-v-b/refkv PR #73, unmodified, used as one arm |

## Running

```bash
uv sync                       # builds Icechunk from source
export EARTHDATA_TOKEN=...    # an Earthdata Login bearer token, for downloads and the relay
uv run scripts/download.py pr tmin 2017 2018 2019 2020 2021 2022
uv run python bench/build.py pr tmin 2017 2022
(cd bench && uv run python compare.py pr tmin 2017 2022)
```

To count requests at the source, start `uv run python bench/range_server.py 8765 20`
(port, added latency in ms) and set `BENCH_HTTP=http://127.0.0.1:8765/` for the other
scripts. `survey/remote.py` needs the server started with `EARTHDATA_TOKEN` set.

Downloaded granules go to `data/` and stores to `stores/`; neither is committed.

## Caveats

- These are prototypes. The numbers are from one workstation, reading local files or a
  local HTTP server; nothing here was measured against S3.
- `uv sync` does not resolve from a clean checkout at the moment: the zarr-python
  branch reports a version below the 3.1.6 that the VirtualiZarr branch requires. The
  runs used local editable checkouts of the three branches.
- Most of the code and the write-up were produced with Claude Code, directed by
  Max Jones.

## Every option, tested

`eval/` runs sixteen proposed options against the same ten test cases, seven kinds of
edit to a stored array, two worst cases and real Daymet granules. The page is
[docs/evaluation.html](https://maxj-labs.github.io/mismatched-granules/evaluation.html),
generated by `eval/report.py` from `results/eval/*.json`.

| Script | What it does |
|---|---|
| `eval/cases.py` | writes the ten sets of small netCDF4/HDF5 files |
| `eval/arms.py` | one builder per option; `eval/xcodecs.py` holds the codecs and store wrappers that exist only for the evaluation |
| `eval/matrix.py` | every option against every case, compared with the files |
| `eval/unaware.py` | opens every store with released zarr-python and released Icechunk |
| `eval/compose.py` | seven edits (drop the first chunk, the first file, the last chunk; append, insert, prepend and replace a file) that change only chunk references and update nothing else an option keeps |
| `survey/prevalence.py` | from public CMR metadata, how often collections receive files late: produced after files holding newer data |
| `examples/reproduce.py` | a short in-memory demonstration of the difference between position and key; needs only the zarr-python branch |
| `eval/scaling.py` | growth with the number of chunks, in two worst cases |
| `eval/perf.py` | timing and request counts on Daymet behind `bench/range_server.py` |
| `eval/without_icechunk.py` | the same arrays as Kerchunk references |
| `eval/tensorstore_probe.py` | cost of TensorStore's stack driver as layers grow |
| `eval/storybook.py` | builds [docs/storybook.html](https://maxj-labs.github.io/mismatched-granules/storybook.html) |

They need the zarr-python and VirtualiZarr branches named on the overview page, and an
Icechunk wheel built from `feat/chunk-index-prefix` (which contains `feat/virtual-ref-prefix`).
